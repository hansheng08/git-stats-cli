### 檢查項目與量測方式
**C1 旗標相容性與輸出一致性（R-01）**
- 對 fixture 逐一執行 ARCHITECTURE §4.1 的 4 個指令（含 `--include-merges` 與未加兩種），記錄每個指令的 exit code 與 stderr。
- 保存 `git log` 原始輸出位元組（`raw-<job>.bin`），比較各 job 間是否完全相同；不同就列出差異所在的 commit／欄位。
- 個人設定干擾測試：`GIT_CONFIG_GLOBAL` 指向含下列設定的檔案再跑一次，結果須與無設定時相同：`diff.renames=false`、`log.mailmap=true`、`log.showSignature=true`、`log.diffMerges=first-parent`、`core.quotepath=true`、`diff.external=false-cmd`、`color.ui=always`、`i18n.logOutputEncoding=ISO-8859-1`。
- 唯讀：執行前後比對 `git status --porcelain`、`git for-each-ref`、`.git/config` 與 `.git/index` 的修改時間（AC-35、TEST_PLAN D-19）。
- fixture HEAD SHA 在 4 個 job 間是否完全相同（ARCHITECTURE §12.1.4 `EXPECTED_SHA` 前提）。

**C2 效能（R-02、NFR-01／02）**
- 用 `gen` 產生 1,000 與 10,000 commit repo（seed 固定為 1）；另選 1 個真實公開 repo（commit 數 8,000～20,000，以 `git rev-list --count HEAD` 記錄；clone 屬 PoC 準備步驟，可連網）。
- 每個情境：1 次暖機＋5 次正式，記錄中位數與最大值；範圍 `--since 1970-01-01 --until 2099-12-31`。
- 另跑「不加 `-M`」對照組，量化改名偵測成本。
- 記錄：總時間、git 子程序時間、解析＋彙總時間、峰值記憶體（Linux `/usr/bin/time -v`、macOS `/usr/bin/time -l`、Windows `Get-Process` 的 `PeakWorkingSet64`）、runner 的 CPU 核心數與記憶體（`nproc`／`sysctl`／`Get-CimInstance`）。

**C3 Windows 時區：TZ vs tzutil（R-04-a，TechLead R-04）**
在 `windows` job 依序執行，每步把 probe 輸出的時區資訊與 AC-11 判斷結果存檔：
1. 記錄 `tzutil /g` 的原始值（最後必須還原）。
2. 不設 `TZ`，`--tz-mode os`：記錄 `time.Local` 名稱與 2025-12-31T23:30:00-08:00 這個時間點換算後的本地日期。
3. 設 `TZ=Asia/Taipei`，`--tz-mode os`：確認 `time.Local` **不受影響**（ARCHITECTURE §12.1.6 已從 Go 原始碼查證，這裡實測確認）。
4. 設 `TZ=Asia/Taipei`，`--tz-mode env`（W2：`time.LoadLocation(os.Getenv("TZ"))`，probe 需 `import _ "time/tzdata"`）：確認換算為台北時間；再用 `America/New_York`、`America/Los_Angeles`、空字串、非 IANA 值 `CST-8`、不存在的 `Foo/Bar` 各跑一次，記錄成功或 fallback 到 `time.Local`。
5. `tzutil /s "Taipei Standard Time"`、不設 `TZ`、`--tz-mode os`（W1）：確認換算為台北時間；再用 `"Eastern Standard Time"` 檢查 2026-03-08 夏令時間切換日 00:30-05:00 與 23:30-04:00 兩個時間點都落在 2026-03-08（TEST_PLAN TC-AC11-05）。
6. 比較 W1（Windows 時區資料）與 W2（IANA tzdata）對上述所有時間點換算出的本地日期是否一致。
7. 在 Git Bash（`bash -lc 'echo "TZ=[$TZ]"'`）與 PowerShell 各記錄一次 `TZ` 是否被預設帶入、值是什麼。
8. 記錄加入 `time/tzdata` 前後的 exe 檔案大小差異。
9. 還原 `tzutil /s "<原始值>"` 並再次 `tzutil /g` 確認。
- 交付一張比較表：正確性、三平台一致性、測試需不需要管理員權限、對使用者環境的副作用、Git Bash 帶入 `TZ` 的風險、檔案大小，並**建議 W1 或 W2**（可附條件）。

**C4 非 ASCII 路徑與名稱（R-04-b、NFR-07）**
- 在名為 `測試 資料夾\repo 😀`（macOS／Linux 用 `測試 資料夾/repo 😀`）的路徑建 fixture，內含中文檔名 `說明.txt`、作者「王小明」與 emoji 作者；用 probe 統計，並以 probe 寫出一個中文檔名的輸出檔（模擬 `--output 報告.csv`）。
- 通過條件：exit 0、作者名字與 email 位元組與 fixture 相同、行數正確、輸出檔存在且內容為 UTF-8。

**C5 未簽章執行檔（R-04-c）**
- 自動部分（`windows` job）：`CGO_ENABLED=0 go build -trimpath` 出 `probe.exe`；記錄 `Get-MpComputerStatus` 的 `AntivirusEnabled`／`RealTimeProtectionEnabled`；若 Defender 啟用，用 `MpCmdRun.exe -Scan -ScanType 3 -File <exe>` 掃描並記錄結果。**不確定** GitHub Windows runner 的 Defender 是否啟用，若停用就記錄「runner 無法驗證」。
- **人工部分（Linux 與 CI 都無法驗證，需老闆在真正的 Windows 11 上做，約 5 分鐘，可延後到 G4）**：以瀏覽器下載 artifact 中的 `probe.exe` zip，(a) 在 PowerShell 解壓後執行 `.\probe.exe --help`；(b) 在檔案總管雙擊。記錄是否出現 SmartScreen「Windows 已保護您的電腦」或 Defender 警告、需要按幾下。報告中把這段寫成給老闆的操作步驟，結果欄留白標「待老闆實測」。
- 不得把執行檔上傳到 VirusTotal 等外部服務。

**C6 partial clone 與 `GIT_NO_LAZY_FETCH`（R-03、NFR-04）**
- 建來源 repo（含多個檔案歷史）→ `git clone --bare` → `git -C <bare> config uploadpack.allowFilter true` → `git clone --filter=blob:none --no-checkout file://<bare> pc`。
- 記錄 `git -C pc count-objects -v`，然後**把 bare 來源改名**（讓遠端無法連線）。
- 在 `pc` 分別以「無 `GIT_NO_LAZY_FETCH`」與「`GIT_NO_LAZY_FETCH=1`」跑 §4.1 的 `git log` 指令；記錄 exit code、stderr、`count-objects` 是否增加。再把來源改回原名，重跑「無變數」版本確認是否會自動抓取（用 `GIT_TRACE2_EVENT` 檔案記錄是否出現 fetch 子程序）。
- 測試唯讀偵測做法：`git -C pc config --get extensions.partialclone`、`git -C pc config --get remote.origin.promisor` 的輸出。
- 交付：各 git 版本的行為表，以及建議做法（例如：只設環境變數／偵測到 partial clone 就 exit 1 並說明／只寫 README）。

## 實作限制（介面、檔案位置、命名、可用套件）
- 只用 Go 標準庫（含 `time/tzdata`），不加任何第三方套件。
- 所有檔案只放在 `poc/A-001/` 與 `.github/workflows/poc-a001.yml`。
- git 指令、旗標、環境變數必須與 ARCHITECTURE §4.1／§4.2 **逐字相同**；若發現某旗標在 2.34 不能用，不要自行換旗標「讓它通過」，而是記錄並提出替代旗標的實測結果。
- 執行 git 一律用 `exec.Command("git", args...)` 傳參數陣列，不經 shell。
- fixture 一律套用 ARCHITECTURE §12.1.4 隔離環境（`HOME`／`USERPROFILE`、`GIT_CONFIG_NOSYSTEM=1`、`GIT_CONFIG_GLOBAL`＝空檔、固定作者與日期、`core.autocrlf=false`）。
- workflow 不使用任何 repository secret；只用預設的 `GITHUB_TOKEN`（上傳 artifact 不需另外設定）。
- 時間量測用 `time.Since`（毫秒，整數）。
