> 名詞說明：**半開區間 `[start, end)`** 代表包含 start、不包含 end；迄日當天要整天算進去，所以 end 是「迄日隔天的 00:00」。**sentinel／包裝（wrap）**：Go 用 `errors.Is`／`errors.As` 沿著被包裝的 error 往內找，所以外層的 error 可以標記種類，同時保留原本的訊息。

## 驗收標準（逐條可驗證）
- [ ] **AC-10（單元層）**：給定 `start = 2026-01-01 00:00:00`、`end = 2026-02-01 00:00:00`（同一個固定時區 UTC+8）的 `DateRange`，`Contains` 在下列情況符合預期：
  - `2026-01-01 00:00:00` → true（起日包含）
  - `2026-01-31 23:59:59` → true（迄日最後一秒包含）
  - `2026-02-01 00:00:00` → false（end 不包含）
  - `2025-12-31 23:59:59` → false
  - end 前 1 奈秒 → true
  - 同日區間（`2026-01-15 00:00` 到 `2026-01-16 00:00`）只包含 1/15 當天
  - 比較的是**絕對時間點**：`2025-12-31T23:30:00-08:00`（等於 UTC+8 的 2026-01-01 15:30）→ true；`2026-01-01T00:30:00+09:00`（等於 UTC+8 的 2025-12-31 23:30）→ false
- [ ] **AC-32（單元層）**：`ParseFormat("table")`、`ParseFormat("csv")` 回傳 nil error，而且兩個結果彼此不相等（`!=`）；`"json"`、`"xml"`、`""`、`"CSV"`、`"Table"`、`" table"`、`"table "` 全部回傳非 nil error，同時回傳零值 `model.Format{}`。
- [ ] `NewDateRange`：`start` 早於 `end` 時成功；`start == end`、`start` 晚於 `end` 時回傳非 nil error 和零值 `DateRange{}`。零值 `DateRange{}` 的 `Contains` 對任何時間都回傳 false。
- [ ] `Since()`／`Until()`：`NewDateRange(2026-01-01 00:00 UTC+8, 2026-02-01 00:00 UTC+8)` 的 `Since()` 是 `"2026-01-01"`、`Until()` 是 `"2026-01-31"`；同日區間兩者相同；跨年、閏日（`2028-02-29` 到 `2028-03-01`，`Until()` 是 `"2028-02-29"`）都正確。
- [ ] `apperr`：`Usage(err)`、`Runtime(err)` 包裝後，`errors.Is(wrapped, err)` 為 true，`Error()` 和 `err.Error()` 相同；`IsUsage` 對 Usage 包裝的錯誤（包括再被 `fmt.Errorf("...: %w", ...)` 包一層）回傳 true，對 Runtime、未包裝的 error、`nil` 回傳 false；`Usage(nil)`、`Runtime(nil)` 回傳 `nil`。
- [ ] 型別符合 §5.3：`Commit`、`AuthorStat`、`Options` 欄位名稱與型別逐字一致；`Format`、`DateRange` **沒有匯出欄位**（`go doc ./internal/model Format`、`go doc ./internal/model DateRange` 的 struct 內只顯示 `// Has unexported fields.`）。
- [ ] archtest 通過：`internal/model`、`internal/apperr` 只 import 標準庫（`go test ./internal/archtest/` exit 0）。
- [ ] `go build`、`go vet`、`go test`、`go test -race` 全部 exit 0；`golangci-lint run`（v2.15.0）為 `0 issues.`；`gofmt -l .` 無輸出。

## 實作限制（介面、檔案位置、命名、可用套件）
- 只用 Go 標準庫。`model`、`apperr` 都不 import 任何專案內 package（archtest 與 depguard 會擋）。
- **model**
  - `ParseFormat(s string) (Format, error)`：只接受**完全等於** `"table"` 或 `"csv"` 的字串；不 trim、不轉小寫。錯誤時回傳 `Format{}` 和一個普通 error（`errors.New`／`fmt.Errorf`）。model 不能 import apperr，「未知格式＝Usage（exit 2）」由之後的 `cli` 包裝（ARCHITECTURE §8）；錯誤字串的內容不屬於驗收範圍，給使用者看的訊息由 `cli/messages.go` 負責。
  - `NewDateRange(start, end time.Time) (DateRange, error)`：`start.Before(end)` 才成功，否則回傳 `DateRange{}` 和普通 error。不轉換時區，原樣保存傳入的 `time.Time`。
  - `Contains(t time.Time) bool`：`!t.Before(start) && t.Before(end)`（絕對時間點比較，ARCHITECTURE §6 第 1 點）。
  - `Since()` 回傳 `start.Format("2006-01-02")`；`Until()` 回傳 `end.AddDate(0, 0, -1).Format("2006-01-02")`。依 §6 第 1 點，`end` 是迄日隔天 00:00，所以往前一天就是原始迄日。不要另外儲存字串欄位。
  - receiver 用值接收者（`func (r DateRange) ...`），符合 §5.3 的寫法。
- **apperr**（ARCHITECTURE §8 只規定 `apperr.Usage(...)`／`apperr.Runtime(...)` 包裝，以及未包裝的 error 視為 1。以下是 TechLead 依此補上的最小 API，不要多做）：
  ```go
  // Usage marks err as a usage error (exit code 2). Usage(nil) returns nil.
  func Usage(err error) error
  // Runtime marks err as a runtime error (exit code 1). Runtime(nil) returns nil.
  func Runtime(err error) error
  // IsUsage reports whether err or any error it wraps was marked by Usage.
  func IsUsage(err error) bool
  ```
  - 內部用一個**未匯出**的錯誤型別（例如 `type kindError struct{ kind kind; err error }`），實作 `Error()`（回傳 `err.Error()`）和 `Unwrap()`。`IsUsage` 用 `errors.As` 判斷。
  - 不匯出 kind 型別或常數，也不提供 `IsRuntime`（未包裝的 error 和 Runtime 一樣都是 exit 1，`cli` 只需要 `IsUsage`）。
- 檔名 `snake_case.go`；commit 訊息 `[ClaudeCode] T-002 model 型別與 apperr 錯誤種類`。
- golangci-lint 規則以 main 上的 `.golangci.yml` 為準（errorlint：比較 error 一律用 `errors.Is`／`errors.As`，不用 `==`；forbidigo：非測試碼不可以 `panic`）。
