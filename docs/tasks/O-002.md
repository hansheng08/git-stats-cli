# O-002：收緊 Claude Code 的 git push 權限（deny 規則＋PreToolUse hook）

- 撰寫者：SRE（任務單擁有者）
- 版本：v0.1（2026-11-22）
- 起因：TechLead Review PR #2 時發現，O-001 的 `.claude/settings.json` 用萬用字元允許 `git push origin task/*`、`fix/*`，這些規則也會符合 `git push origin task/x:refs/heads/main`（把本地分支推到遠端 main）等危險寫法。
- 交棒模式：A（Hansheng 在本機執行）

> 名詞說明
> - **refspec**：`git push` 的「本地:遠端」寫法，例如 `task/x:main` 代表把本地 `task/x` 推到遠端 `main`；`:task/x`（冒號前面空白）代表**刪除**遠端分支；前面加 `+` 代表強制覆寫。
> - **PreToolUse hook**：Claude Code 在執行每個工具（例如 Bash 指令）**之前**會呼叫的外部程式，程式可以回覆 allow、deny 或 ask。
> - **permission rule（權限規則）**：`.claude/settings.json` 的 `allow`／`ask`／`deny` 清單，用前綴加 `*` 比對指令文字。這只是防呆，同一個動作換個寫法（例如 `git -C . push`）就比對不到，不是安全邊界。
> - **分支保護（branch protection）**：GitHub 端的設定，擋住對 main 的直接推送與 force push，是真正的最後防線。

- 目前的 `.claude/settings.json`（O-001 產出）與 `docs/tasks/O-001.md`「實作限制 B」。

  - Permissions：https://code.claude.com/docs/en/permissions （deny → ask → allow 依序比對、第一個符合的決定結果；`*` 萬用字元；結尾 `:*` 等同結尾萬用字元；複合指令 `&&`、`;`、`|` 會拆開逐段比對；deny 規則比對不到 `git -C . push`、`sh -c '…'` 這類變形）
  - Hooks：https://code.claude.com/docs/en/hooks （PreToolUse 的 stdin JSON 含 `tool_name`、`tool_input.command`、`cwd`；回覆 `hookSpecificOutput.permissionDecision` 為 `allow`／`deny`／`ask`；exit 2＝阻擋；`onFailure: "block"` 讓 hook 無法執行或逾時也阻擋；hook 回 `allow` 時 deny／ask 規則**仍會**被檢查）

## 目標
讓 Claude Code 自動放行的 push **只有**一種：把「目前所在的 `task/*` 或 `fix/*` 分支」推到 origin 的同名分支。其餘所有 push 寫法（refspec 含冒號、刪除、強制、批次推送、推 main、推 tag、帶 `-C`／`-c` 的 git 全域選項、經由 `sh -c` 等包裝）一律拒絕。

## 設計（三層）
1. **hook（主要關卡，嚴格白名單）**：新增 PreToolUse hook `pushguard`（Go 程式，只用標準庫）。凡是指令中出現「git 的 push 子指令」，只有完全符合下列格式才回 `allow`，其他一律回 `deny`：
   ```
   git push origin <B>
   git push -u origin <B>
   git push --set-upstream origin <B>
   ```
   其中 `<B>` 必須**等於目前分支**（以 hook 輸入的 `cwd` 執行 `git -C <cwd> symbolic-ref --quiet --short HEAD` 取得），且符合 `^(task|fix)/[A-Za-z0-9][A-Za-z0-9._-]*(/[A-Za-z0-9][A-Za-z0-9._-]*)*$`，不含 `..`、不以 `.lock` 結尾。不是 push 的指令，hook 不表示意見（exit 0、無輸出），交給原本的權限規則。
2. **settings.json 的 allow 移除 push**：刪掉 O-001 的 4 條 `Bash(git push … task/*|fix/*)` allow 規則。合法的 push 改由 hook 回 `allow` 放行；hook 若沒有放行，就會落到「詢問人類」（模式 B 的 `-p` 無人回應＝拒絕），屬於安全的失敗方向。
3. **settings.json 的 deny 補強（防呆）**：保留 O-001 既有的 push deny 規則，再補上下表新增的規則。
4. **GitHub 分支保護（最後防線，不在本任務範圍）**：main 需要 PR、`ci-ok` 必過、禁止 force push 與刪除。由 Hansheng 在 GitHub 設定；報告中列為「需要人類決定的問題」並說明目前是否已設定（看不到就寫「不確定」）。

## 實作限制

### A. pushguard 行為規格
- 輸入：stdin 的 JSON（`tool_name`、`tool_input.command`、`cwd`）。`tool_name` 不是 `Bash` 或 `PowerShell` → exit 0 無輸出。
- **判斷是不是 push**（要避免誤判 `git commit -m "push fix"` 這類字串）：
  1. 以簡易 shell 斷詞處理單引號、雙引號、反斜線，並在 `&&`、`||`、`;`、`|`、`&`、換行處切成多段。
  2. 每段去掉開頭的環境變數指派（`X=y`）與包裝指令（`env`、`command`、`builtin`、`time`、`timeout <n>`、`nice`、`nohup`、`stdbuf …`、`xargs`）。
  3. 第一個字的檔名（去掉路徑與 `.exe`）若是 `git`：略過 git 全域選項（`-C <x>`、`-c <x>`、`--git-dir=…`、`--work-tree=…`、`--namespace=…`、`-p`、`--no-pager`、`--bare` 等，任何以 `-` 開頭的字），第一個非選項的字就是子指令；子指令為 `push` 即視為 push。
  4. 第一個字若是 `sh`、`bash`、`zsh`、`dash`、`pwsh`、`powershell`、`cmd`、`eval`、`Invoke-Expression`、`iex`，且整段文字含 `push` → 視為 push（一律拒絕，因為無法安全解析）。
  5. 斷詞失敗（例如引號不成對）時：原始文字同時含 `git` 與 `push` → 視為 push。
- **允許條件（全部成立才 `allow`）**：
  1. 原始指令只有**一段**（沒有任何 `&&`、`||`、`;`、`|`、`&`、換行），且不含 `` ` ``、`$(`、`${`、`<`、`>`、`*`、`?`、`[`、`~`、`\`、引號。
  2. 斷詞後恰為 `git push origin <B>`、`git push -u origin <B>` 或 `git push --set-upstream origin <B>`（`git` 前不得有環境變數或包裝指令，`git` 與 `push` 之間不得有任何選項）。
  3. `<B>` 不含 `:`、不以 `+` 開頭、不是 `HEAD`／`main`／`master`，符合「設計」第 1 點的正規表示式，而且等於目前分支。
- 其餘 push 一律 `deny`，`permissionDecisionReason` 寫明原因並提示正確寫法，例如：`pushguard: only "git push [-u] origin <current task/ or fix/ branch>" is allowed; got refspec with ":"`。
- 輸出：只在 stdout 印一個 JSON 物件並 exit 0：
  ```json
  {"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}
  ```
  不是 push 時不印任何東西、exit 0。不要用其他 exit code（官方文件：0 與 2 以外的 exit code 會被視為失敗；在 `onFailure: "block"` 下會擋住**所有** Bash 指令）。
- 取目前分支：`exec.Command("git", "-C", cwd, "symbolic-ref", "--quiet", "--short", "HEAD")`，逾時 5 秒；失敗即視為取不到分支。為了測試，把「取目前分支」做成可注入的函式。
- 程式碼放在 `.claude/hooks/pushguard/`，`package main`，只用標準庫（`encoding/json`、`os`、`os/exec`、`regexp`、`strings`、`time` 等）。這個資料夾以 `.` 開頭，不受 archtest 與 `./...` 掃描；在報告註明這點。

### B. `.claude/settings.json` 變更
1. 從 `permissions.allow` 刪除：
   ```
   "Bash(git push -u origin task/*)", "Bash(git push -u origin fix/*)",
   "Bash(git push origin task/*)",    "Bash(git push origin fix/*)"
   ```
2. 在 `permissions.deny` 新增（注意：不得有以 `:*` 結尾的規則）：
   ```
   "Bash(git push *:main*)",
   "Bash(git push *:refs/*)",
   "Bash(git push *:master*)",
   "Bash(git push * --force-with-lease*)",
   "Bash(git push * --force-if-includes*)",
   "Bash(git push --prune*)",
   "Bash(git push * --prune*)",
   "Bash(git push * --mirror*)",
   "Bash(git push * --all*)",
   "Bash(git push --branches*)",
   "Bash(git push * --branches*)",
   "Bash(git push * --follow-tags*)",
   "Bash(git push --follow-tags*)",
   "Bash(git push * --receive-pack*)",
   "Bash(git push * --exec*)",
   "Bash(git push * --delete*)",
   "Bash(git push * -d)",
   "Bash(git push * main*)",
   "Bash(git push * master*)",
   "Bash(git -C * push*)",
   "Bash(git -c * push*)",
   "Bash(git --git-dir* push*)",
   "Bash(git --work-tree* push*)"
   ```
3. 新增頂層 `hooks`：
   ```json
   "hooks": {
     "PreToolUse": [
       {
         "matcher": "Bash|PowerShell",
         "hooks": [
           {
             "type": "command",
             "command": "go",
             "args": ["-C", "${CLAUDE_PROJECT_DIR}", "run", "./.claude/hooks/pushguard"],
             "timeout": 60,
             "onFailure": "block"
           }
         ]
       }
     ]
   }
   ```
   - 若當下 Claude Code 版本不支援 exec 形式（`args`）或 `onFailure`，改用官方文件的對應寫法並在報告說明；**不得**因此拿掉 `onFailure: "block"` 的效果（找不到等效寫法就停下回報）。
   - SRE 已在 Linux 驗證：`go -C <repo> run ./.claude/hooks/pushguard` 從任何工作目錄都能執行；直接 `go run <絕對路徑>` 在 repo 外會因找不到 `go.mod` 失敗，所以必須用 `-C`。
