> 名詞說明
> - **CI（Continuous Integration，持續整合）**：每次推送程式碼，雲端自動建置、檢查、測試。
> - **workflow**：GitHub Actions 的一份自動化流程設定檔（YAML）。
> - **required check（必過檢查）**：在 GitHub 分支保護裡設定「這個檢查沒綠燈就不能合併」。
> - **govulncheck**：Go 官方的相依套件漏洞掃描工具，只回報程式「真的有呼叫到」的漏洞。
> - **gitleaks**：掃描 git 歷史裡是否不小心 commit 了密碼、Token 的工具。
> - **actionlint**：檢查 GitHub Actions workflow 語法與常見錯誤的工具。
> - **SHA 釘選**：引用第三方 Action 時寫完整 commit SHA 而不是 `v7` 這種可被移動的標籤，防止供應鏈攻擊。

## 實作限制

### A. `.github/workflows/ci.yml` 規格
- 名稱：`name: ci`。
- 觸發：
  ```yaml
  on:
    push:
      branches: ['**']
    pull_request:
      branches: [main]
    workflow_dispatch:
  ```
- `permissions: { contents: read }`；`concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`。
- 第三方 Action 一律 SHA 釘選（以下 SHA 於 2026-11-22 由 SRE 以 `git ls-remote` 查得；若你的環境查到不同值，停下並在報告說明，不要自行換版本）：
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # v7.0.1`
  - `actions/setup-go@d8cbb8045d7f43706b9177cceb36c1f91a6644d5  # v7.1.0`
  - `golangci/golangci-lint-action@ba0d7d2ec06a0ea1cb5fa41b2e4a3ab91d21278a  # v9.3.0`
- 每個用到 checkout 的 job：在 checkout **之前** 加一步 `git config --global core.autocrlf false`（避免 Windows 改動換行，讓 golden file 與行數測試穩定）。
- `setup-go`：`go-version-file: go.mod`、`cache: true`（`cache-dependency-path: go.sum`，go.sum 不存在時 setup-go 會警告但不失敗；若會失敗，改為只在 go.sum 存在時開 cache）。
- 各 job：
  1. `lint`（`runs-on: ubuntu-24.04`）：checkout → setup-go → `golangci-lint-action` with `version: v2.15.0`（全部以 go.mod 存在為條件）。
  2. `build-test`（`name: build-test (${{ matrix.os }})`，矩陣如 AC-O3）：checkout → setup-go → `go version` → `git --version`（記錄各平台 git 版本，TEST_PLAN §8 要求）→ `go build ./...` → `go vet ./...` → `go test ./...`。shell 一律用 `bash`（Windows runner 內建 Git Bash），寫在 `defaults.run.shell: bash`。
  2a. `build-test-git-min`（`name: build-test (git-min)`；`runs-on: ubuntu-24.04`；`container: ubuntu:22.04`）：
     - job 層級 `env: { GIT_MIN: "2.34" }`（PoC A-001 若把最低 Git 版本調高，屆時由 SRE 另開 O-xxx 同時調整 `GIT_MIN` 與容器映像；本任務不預先處理）。
     - checkout **之前**：`apt-get update && apt-get install -y --no-install-recommends git ca-certificates tar gzip`（容器預設沒有 git；沒有 git 時 actions/checkout 會改用 API 下載、沒有 `.git`）。
     - `git --version`，並以 `git --version | grep -E "^git version ${GIT_MIN//./\\.}(\.|$)"` 斷言版本，不符就失敗（印出實際版本）。
     - checkout → `git config --global --add safe.directory "$GITHUB_WORKSPACE"` → setup-go（`go-version-file: go.mod`）。
     - 以**非 root** 使用者執行測試（TEST_PLAN 的權限測試需要非 root）：`useradd -m tester`、`chown -R tester "$GITHUB_WORKSPACE"`，再用 `su tester -c '...'`（需帶入 `PATH` 與 Go 路徑）執行 `go build ./...`、`go vet ./...`、`go test ./...`。若非 root 執行在容器中不可行，停下並在報告說明，不要改成 root 執行後當作通過。
     - 有 go.mod 才執行 Go 步驟（同 AC-O9）。
  2b. `offline-test`（ubuntu-24.04）：checkout → setup-go → `go mod download` → `go test -count=1 -run '^$' ./...`（只編譯、暖快取）→ 無網路執行：
     ```bash
     sudo unshare --net -- sudo -u "$(id -un)" env "PATH=$PATH" "HOME=$HOME" GOFLAGS=-mod=mod GOPROXY=off GOTOOLCHAIN=local \
       "GOCACHE=$(go env GOCACHE)" "GOMODCACHE=$(go env GOMODCACHE)" go test -count=1 ./...
     ```
     先在同樣的 namespace 內執行一次 `curl -sS --max-time 5 https://proxy.golang.org >/dev/null && exit 1 || echo offline-ok`，證明網路確實不通（連得上就讓 job 失敗）。若 `unshare` 在 runner 上不可用，job 應失敗並在報告說明，**不要**改用較弱的檢查。
  3. `vulncheck`（ubuntu-24.04）：checkout → setup-go → `go run golang.org/x/vuln/cmd/govulncheck@v1.10.0 ./...`。
  4. `secret-scan`（ubuntu-24.04）：checkout `fetch-depth: 0` → 下載 `https://github.com/gitleaks/gitleaks/releases/download/v8.30.1/gitleaks_8.30.1_linux_x64.tar.gz` 與同版本 `gitleaks_8.30.1_checksums.txt` → `grep ' gitleaks_8.30.1_linux_x64.tar.gz$' gitleaks_8.30.1_checksums.txt | sha256sum -c -` → 解壓 → `./gitleaks git --redact --no-banner --exit-code 1 .`。此 job 不依賴 go.mod，永遠執行。
  5. `scripts-lint`（ubuntu-24.04）：檔案存在才執行：`shellcheck scripts/install.sh`（runner 內建 shellcheck；先印 `shellcheck --version`）；`pwsh -NoProfile -Command "Install-Module PSScriptAnalyzer -RequiredVersion 1.25.0 -Scope CurrentUser -Force; \$r = Invoke-ScriptAnalyzer -Path scripts/install.ps1 -Severity Warning,Error; \$r; if (\$r) { exit 1 }"`。兩個檔案都不存在時印 `::notice::` 並成功。
  6. `goreleaser-check`（ubuntu-24.04）：`.goreleaser.yaml` 存在才執行：以 `go install github.com/goreleaser/goreleaser/v2@v2.20.3` 安裝後執行 `goreleaser check` 與 `goreleaser release --snapshot --clean`（只在本機產出 `dist/`，不發佈、不需要 Token）。不存在時印 `::notice::` 並成功。
  7. `ci-ok`（ubuntu-24.04）：`needs: [lint, build-test, build-test-git-min, offline-test, vulncheck, secret-scan, scripts-lint, goreleaser-check]`、`if: always()`，步驟檢查 `${{ contains(needs.*.result, 'failure') || contains(needs.*.result, 'cancelled') }}` 為 true 就 `exit 1`。
- 檔案「存在」的判斷：job 或 step 層級用 `hashFiles('<path>') != ''`。
